# Kontakt native loading contract audit

2026-10-12. Scope: Kontakt loading, KSP initialization, physical script slots, UI resources and sample admission. This is a source and documentation audit, **not** a fresh Kontakt execution or a claim of Kontakt equivalence or faster loading. The older v1 implementation is historical evidence only; a v1/v2 agreement cannot decide native behavior.

## Documented contract and local implication

| Topic | NI's documented rule (D) | Worktree observation and open question (R/I) |
| --- | --- | --- |
| Init and persisted state | `on init` runs after successful compile when an instrument/script preset is loaded, after engine restart, and on snapshot types 0/2. Saved `make_persistent` values are read **at the end** of init; `read_persistent_var` reads one early during init. `on persistence_changed` runs after init and on snapshot recall. `make_instr_persistent` is instrument-only. [Callbacks](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/callbacks), [Variables](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/variables) | `sampler-ksp/src/eval.rs` runs init, restores saved variables, and either runs or schedules `persistence_changed` (about lines 300–350). This is structurally aligned with documented order, but exact saved-value mapping, early reads, function calls, callback side effects and UI state need native values. `KSP_SEMANTICS.md` identifies historical `!` array and snapshot-scope issues; recheck present code before asserting they persist. |
| Snapshot scope | `set_snapshot_type` is global across five slots. Types 0/2 rerun init, 1/3 do not; 2/3 save only KSP variables. Recall resets audio and deletes active events. [General Commands](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/general-commands) | A snapshot is a state transition with live-voice and script-slot effects, not just an overlay on file values. `sampler-ksp/src/eval.rs` has snapshot handling; the older audit's “always rerun init” finding is historical until an end-to-end recall probe. |
| Callback completion and work | `on async_complete` carries the originating async ID and success/failure status. File loading/saving is asynchronous except documented mode 1/2 array loads in `on init`; mode 0 dialogs do not block the callback. `wait_async` waits for a valid pending operation; a finished/invalid ID continues. [Callbacks](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/callbacks), [Load/Save](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/load-save-commands), [Time-Related Commands](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/time-related-commands) | `sampler-ksp/src/eval.rs` has a finite init fuel and schedules `persistence_changed` if it may suspend; `WaitAsync` in init has special MIDI completion handling. `sampler-ksp/src/lower.rs` emits a runtime MIDI wait. These are implementation policies; NI does not publish an equivalent fuel count or a general permission to skip/reorder side effects. An exhausted initializer must retain a precise diagnostic and cannot be reported as a successfully loaded native equivalent. |
| Slot and engine address | `$CURRENT_SCRIPT_SLOT` is zero-based. `get/set_engine_par` address by group, slot and generic: group `-1` for instrument/bus/main, physical slot zero-based for effects/modulators, and generic for send/insert/main bus, bus offset, or modulator target as applicable. [Built-in Variables](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/built-in-variables-and-constants), [Engine Parameter Commands](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/engine-parameter-commands) | `sampler-kontakt/src/parity.rs` enumerates every physical script record; `load.rs` retains `behavior.slot` in warnings and binds automation by source slot. Keep that physical identity through cache, initialization, callback instance and UI ID. `KSP_SEMANTICS.md` records that some historical engine reads returned a write mirror/zero instead of the authored module value; an installed-version readback test is needed per parameter and address, not a guessed conversion law. |
| UI and assets | `load_performance_view` loads one Creator Tools `.nckp` per script slot, from `performance_view` in the resource container, only during init, and its controls are KSP-accessible. It cannot be combined with `make_perfview`. `get_font_id` requires a PNG in `pictures`, with a specific font-sheet format, and is init-only. UI position can be changed later; pixel and grid parameter systems cannot be mixed. [UI Commands](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/user-interface-commands), [Resource Container](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/resource-container) | `sampler-kontakt/src/load.rs` parses NCKP before KSP init and projects UI after script compilation; `resources.rs` indexes loose/container assets and reports failures. `sampler-ksp/src/nckp.rs` records unsupported fields. This is an implementation shape, not proof of native pixels, font metrics, widget order or gesture behavior. Resource identity and missing-asset diagnostics should survive warm cache and UI reconstruction. |
| DFD/preload | DFD keeps a small sample prefix in RAM and streams the rest. The instrument's DFD preload size applies to groups in DFD source mode; NI exposes a background-loading option that may allow notes before all samples are loaded, with possible glitches. A global option can override an instrument's stored preload size. [Kontakt Classic View](https://docs.native-instruments.com/ni-tech-manuals/kontakt-manual/en/classic-view), [Options Dialog](https://docs.native-instruments.com/ni-tech-manuals/kontakt-manual/en/options-dialog) | `sampler-kontakt/src/stream.rs` sizes resident heads from measured read latency and a policy; `load.rs` resolves headers and opens a streamer before plan lowering. This is a different admission policy from NI's documented controls. Preserve authored DFD/preload metadata for diagnostics; compare cold-note readiness and memory to native under matched source mode, storage and global override. Do not equate a KONTRA head size with NI's DFD setting. |

NI also documents that `load_array` in init implicitly makes the array persistent, so a saved value can overwrite freshly loaded data at the end of init; an early `read_persistent_var` avoids that order hazard. This is a high-value synthetic native probe because it crosses file I/O, persistence and callback order. [Load/Save Commands](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/load-save-commands). NI's `set_zone_par` and `set_sample` documentation says init calls are synchronous, outside-init calls produce async IDs, and since Kontakt 7.2 some work is delayed to first `wait` or callback end. This is a version-specific batching rule, not a general guarantee for every command. [Zone Commands](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/zone-commands).

## Small loader changes justified by this contract

1. **Immutable source facts before execution.** Keep physical program/script-slot identities, declarations, authored module addresses, saved-value types, DFD settings, asset references and version/profile in one immutable in-memory snapshot. An ephemeral digest may identify protected script bytes; never write those bytes, decrypted keys or PCM into an audit artifact. The existing `cache.rs` caches translated instrument and `CachedInit` without sample PCM; extend its stamp to cover dependency content/version, runtime/schema/profile, relevant host controls and library resource generation. A file size/mtime/inode stamp and dependency mtimes are useful fast rejection but can miss same-metadata edits. This is an implementation recommendation (I), not an NI cache requirement.
2. **Stage observable outcomes.** Give decode, source translation, KSP compile, init, persistence, resource resolve, sample headers, preload and UI projection separate success/failure/pending diagnostics keyed by program and physical slot. Keep a failed script/resource visible in the report even when other slots remain playable. Existing `instrument.unsupported`, scan phases and `PersistenceCompletion` supply most of the vocabulary; avoid collapsing “pending” into “passed.”
3. **Publish one coherent generation.** Build immutable playable metadata and necessary sample heads away from the audio callback. Attach script callback state, source-generation IDs, resource handles and UI projection to that same generation, then commit when its declared admission requirements pass. A failed or canceled candidate leaves the old generation active; a stale worker completion checks generation plus operation ID before publication. Retire old audio/UI/resource owners only after their voices, tails and callbacks release them. This is a recommended architecture, not a claim that NI uses the same protocol.
4. **Keep KSP semantics in KSP.** Share bounded job dispatch and generation ownership with other frontends, but retain KSP-specific callback order, integer values, persistent names/scopes, async IDs and physical engine addresses. A new cross-format language or guessed DSP law would hide the exact differences the native captures must establish.

These changes target correct admission and debuggability. They do not establish native parity or any CPU/RAM/loading-speed win. Such claims require licensed, versioned, matched-quality captures and comparative measurements.

**Immediate source finding (R):** `sampler-kontakt/src/cache.rs::store_in` serializes `Head { instrument: Cow::Borrowed(&kontakt.instrument), states, ... }` to a product-cache file. `sampler_ir::Behavior` includes `source`, so the current schema appears capable of writing translated/decrypted script source to disk even though it omits PCM. No cache file or protected script was opened for this audit. Before using that cache on protected instruments under a no-decrypted-source-on-disk policy, disable those entries or redesign the schema around safe non-source metadata and re-read/compile source in memory. Audit `CachedInit` for source-derived text before admitting it to a persistent schema; file permissions alone do not satisfy the policy.

**Follow-up implementation:** The product cache now rejects any instrument containing a `Behavior` or nonempty cached script-initialization state before creating a cache directory or serializing `Head`. It also refuses to restore script-bearing entries and bumps the cache stamp, making old entries misses without reading their payload. Script-free instruments retain metadata-cache roundtrips and resource invalidation. This deliberately loses the warm script-initialization shortcut for scripted Kontakt programs, so their initializers run on each load; no load-time or memory improvement is claimed. The original source bytes remain in memory for execution, and this change neither inspects nor deletes preexisting user cache files. Synthetic tests check a script marker never reaches a product-cache file and a script-free entry still reloads. The eight focused `sampler-kontakt` cache tests passed via the heavy-job wrapper; no licensed library or native plugin was opened. A later safe cache schema would need explicit source-free serialization and rehydration contracts for saved state, physical slots and current resources.

## Native capture matrix to resolve current uncertainties

Use an original, unprotected fixture saved with the installed Kontakt build, plus a small representative licensed instrument only where needed. Log installed Kontakt version, instrument digest, script-slot layout, resource setting, snapshot mode, preload/global override, MIDI hash, transport/host state, and exact KSP-visible values. Capture Kontakt first; run the same input through v1/v2 afterward. Treat any v1/v2 agreement as one implementation result.

The existing [reference protocol](../architecture-v2/REFERENCE_PROTOCOL.md) requires a calibrated 48 kHz chain, pinned controls and repeat captures under low host load. The harness starts a Wine/Xvfb Kontakt session and is therefore a heavy native job; it was **not** run during this source audit. If this reference host cannot pass its calibration/version/route gates, mark each matrix row **native unknown**, retain only the official documentation and source findings, and defer performance or equivalence claims. A native result must preserve per-run receipts and compare supported outcomes; never save decrypted scripts, samples, keys or protected PCM as an audit artifact.
