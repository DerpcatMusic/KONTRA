## Contributor #1274: strengths, overlap and blockers

The PR changes 266 paths in the fetched diff. The GitHub headline's library
numbers are author-reported measurements, not independently reproduced here.

**What the contributor does well:** parser and language fixes address causes
rather than compensating in the mixer. Escaped quotes in KSP, Kontakt 8 private
script records, note-duration semantics and PGS capacity explain concrete
library failures. Offline rendering and repeatable reference captures make
regressions more observable. Hot Solo maps onto the existing shared amp and
EQ mechanism, which fits the one-engine philosophy. Its comments explicitly
limit its fitted response to one operating point.

**What current code does better:** shared cell input already supports both
integer and real tables, with one gesture and routing path. Keep it when
adding UVI callbacks. Existing preallocated PGS storage has a real-time resource
bound, although its 64-key ceiling loses valid instruments; removing that
ceiling must preserve bounded callback behavior. The correct combination is
instrument-specific preparation/admission, not silent truncation or arbitrary
allocation in the callback.

Verified blockers at the pinned contributor head:

1. `crates/engine/engine/src/pgs.rs`: `PgsCreateKey` uses `vec![0; len]` and
   grows `ints`; string-key creation grows `texts`. There is no preparation-only
   guard on these actions. Reserve admitted keys off audio and explicitly
   diagnose requests beyond the prepared budget. Prove callback allocation
   freedom with a counting allocator and more than 409 keys.
2. `crates/engine/engine/src/script.rs` and `midifile.rs`: `MfInsertEvent`
   calls `MidiFile::insert`, which pushes to `events` and inserts into `order`.
   `MfSetBufferSize` only records an integer; it does not reserve storage.
   Removed events remain in the vectors, so repeated remove/insert cycles can
   grow storage despite returning buffer credits. Use a prepared bounded pool
   and test repeated reuse without allocation or unbounded shifting.
3. `crates/dsp/delay/src/diffusion.rs`: `MAX_RING=4096`, `MAX_TAP=2048` and
   `clamp_tap` silently shorten larger taps. `effects/src/processors.rs` scales
   lengths with render rate, so a valid reference-rate delay can hit this bound
   at higher rates. Size buffers during preparation and verify equal delay
   seconds, stable tails and block independence at 44.1/48/96/192 kHz.
4. `crates/engine/effects/Cargo.toml` adds a dev-dependency on the Kontakt
   adapter to test Hot Solo. Put the translator-to-engine integration test
   above both layers, preserving the common engine's dependency direction.
5. `tools/parity-corpus` introduces reference recordings. Recording provenance
   and redistribution permission need review before copying those assets into
   a release-bearing branch. Existing `docs/LEGAL.md` does not grant that
   permission. This is an unresolved provenance question, not a legal finding.

An older review objected to file I/O in `MfInsertFile`. At the reviewed head,
that action is guarded by `self.building`, true during construction and false
before rendering. Do not repeat the obsolete objection as an unfixed defect.
The current callback-allocation objections above are separate.

Suggested extraction order: escaped-string parsing with compiler tests;
private-script decoding with bounded malformed-input fixtures; note-duration
and variable identity semantics; prepared PGS capacity; offline renderer and
portable tooling tests; DSP modules after rate/parameter/tail tests. Each can
be independently reverted. Do not copy a second renderer or format-specific
gesture implementation to obtain the parser fixes.

KONTRA's direction is sound: importers describe instruments, preparation owns
resolution, and one engine owns notes, voices, DSP and mixing. The primary
threats are incomplete catalogs, silent semantic loss and unbudgeted callback
services, rather than a lack of additional renderers.

## Reuse decisions and remaining experiments

These are benchmark/research decisions, not replacement recommendations:

- [rubato](https://github.com/HEnquist/rubato): benchmark prepared/offline
  resampling separately from dynamically pitched per-voice playback. Reproduce
  current alias rejection, onset alignment and phase continuity before changing
  the native interpolator.
- [fft-convolver](https://github.com/neodsp/fft-convolver): compare long-IR CPU,
  memory, exact onset, arbitrary block sizes, reset and tail behavior with
  `crates/dsp/reverb`; do not trade onset latency for a favorable CPU number.
- [Signalsmith Stretch](https://github.com/Signalsmith-Audio/signalsmith-stretch):
  prototype behind a replaceable preparation/DSP interface only after measuring
  latency, reset, transients, formants, callback allocation and FFI overhead.
- [Shortcircuit XT](https://github.com/surge-synthesizer/shortcircuit-xt): study
  selection, routing and modulation organization. No source import is approved
  by this review. HISE, sfizz, RustySynth and XSynth still need the full requested
  capability, maintenance and license comparison.

No atomic-page replacement, SIMD layout rewrite, stretch adoption or native
format implementation is justified by this merge triage alone. The full
format-capability matrix, authorized differential corpus, cache bake-off,
current resampler/convolver comparisons and script worst-case measurements
remain outstanding. They must not be presented as completed work.
