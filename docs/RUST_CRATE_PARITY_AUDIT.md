## Lua ownership and ABI

The native UI candidate selects `lua54`, `vendored`, `send`. `mlua` handles real Lua evaluation, typed conversions and Rust host bindings; custom code should focus on `.nui` syntax, allowed capabilities, parameter semantics and source maps. Its `send` feature synchronizes VM access with a reentrant mutex. That helps move UI ownership but does not establish suitability for the audio callback. A memory limit rejects growth; it is not a preallocated RT pool. `async` integrates Rust futures and is not Falcon's sample-clock `wait`/`waitBeat`/`spawn` scheduler. [mlua API](https://docs.rs/mlua/0.12.1/mlua/)

`Lua::set_hook` covers the current thread. `set_global_hook` propagates to new threads created by mlua; `Thread::set_hook` is available for individual coroutines. If coroutine capability is later exposed, verify Lua-created and host-created threads, nested protected calls, sticky fuel, cancellation and resumption; do not assume the current single-thread UI hook protects them. Candidate `a7ffb2a` already adds protected-call sticky-budget checks. `Chunk::set_name` and native error traceback can provide execution locations, but generated `.nui` spans still require a lowering map. [Lua hooks](https://docs.rs/mlua/0.12.1/mlua/struct.Lua.html)

Do not alias a second `mlua` dependency with `lua51` in this binary. Published `mlua-sys 0.12.0` declares `links = "lua"`; its build script permits exactly one Lua-family feature. Cargo unions enabled features for a package, and conflicting versions declaring the same native link name cannot coexist in one resolved graph. Renaming the Cargo dependency does not rename native Lua symbols or isolate an ABI. Falcon Lua 5.1 therefore remains deferred until an explicit ABI/binary strategy and allocation/scheduler evidence exist; this audit does not propose implementing such a strategy now. [Published mlua-sys manifest](https://docs.rs/crate/mlua-sys/0.12.0/source/Cargo.toml), [build feature check](https://github.com/mlua-rs/mlua/blob/v0.12.1/mlua-sys/build/main.rs), [Cargo features and native links](https://doc.rust-lang.org/cargo/reference/resolver.html#links)

Falcon has real/boolean/string/table state, element-scoped parameter metadata, default event forwarding and sample-accurate cooperative callbacks. Preserve those distinctions instead of forcing floats through the UI candidate's KSP `i32` connection or replacing KSP's existing event ownership with a generic Lua VM. The [Falcon runtime/UI groundwork](FALCON_RUNTIME_UI_GROUNDWORK.md) records those contracts separately.

## SVG, fonts and device scale

`vello_svg` documents incomplete compound clipping and absent masks/filter effects/patterns. These are directly relevant to the asset candidate's current explicit rejections. Keep the retained path/stroke/gradient/layer route for supported artwork; route the remaining document through resvg rather than hand-implementing filter primitives or silently omitting elements. `resvg::render(&Tree, Transform, &mut PixmapMut)` accepts a root transform and emits sRGB pixels. Apply device scale to physical pixel dimensions and transform while keeping logical layout dimensions stable. [vello_svg limits](https://docs.rs/vello_svg/latest/vello_svg/), [resvg render](https://docs.rs/resvg/latest/resvg/fn.render.html)

Tiny-skia pixmaps use premultiplied RGBA. Convert once at the worker boundary if the MUI image contract expects straight RGBA; do not double-premultiply translucent edges. Validate a partly transparent filtered shape over both light and dark backgrounds. Bound intermediate filter surfaces as well as output/retained cache sizes, and reject oversized work explicitly. A pixels-only cap does not itself bound parser/filter scratch memory. [Pixmap contract](https://docs.rs/tiny-skia/latest/tiny_skia/struct.Pixmap.html)

`usvg::Options` exposes `fontdb`, font and image resolvers. Load scoped embedded font bytes into an owned font database on preparation; use the existing MUI text route for interactive UI text. Reuse usvg's shaping for text inside SVG rather than introducing a second shaping dependency directly. Deterministic font fallback must be declared and tested: default fonts or arbitrary host system fonts cannot prove UI parity. External images must resolve through the existing bounded resource namespace, or fail explicitly. [usvg options](https://docs.rs/usvg/latest/usvg/struct.Options.html)

Feature detail from the cached published manifests: `vello_svg 0.11.0` depends on `usvg ^0.48.0` with its defaults enabled. Turning off vello_svg defaults disables its optional Vello integration, not usvg's text/system-font/memmap features. Directly declaring usvg with defaults disabled cannot subtract features another dependency enabled. Use explicit owned font/image resolvers regardless; inspect feature unification in the eventual build window. No parallel painting/GPU crate or new cache framework is required.

## XML, decoding and DSP

`roxmltree::Document::parse_with_options` already supplies `ParsingOptions { allow_dtd: false, nodes_limit: <bounded>, entity_resolver: None }`. Default node limit is unlimited, so set it deliberately in addition to the file-byte cap. Borrowed node ranges and text positions can feed existing source diagnostics. Preserve XML attributes not yet understood; recognize module names without claiming sonic support. No general archive crate interprets the observed `UFS2` headers. [ParsingOptions](https://docs.rs/roxmltree/latest/roxmltree/struct.ParsingOptions.html)

`src/audio.rs:1109..1125` sends NCW to its specialized reader and other files to `SampleReader::pcm`; despite that helper name, `1152..1192` already uses Symphonia's probe/registry. Adding a proven ordinary FLAC requirement therefore fits the existing abstraction. Symphonia 0.5.5 documents its `flac` feature; the current manifest disables defaults and requests only `aiff,wav,pcm`. Decoder/packet work stays in the existing loading/streaming path, not the audio mixer. The installed UFS inventory does not establish accessible FLAC sample entries. [Symphonia format/codec features](https://docs.rs/symphonia/0.5.5/symphonia/)

The existing realfft convolver has direct-reference and variable-block tests, and existing FX tests exercise no-heap runtime processing. Keep it. Rubato's `process_into_buffer` avoids allocation/blocking after buffer preparation; allocating whole-clip APIs trim delay. SIMD has scalar fallback. Future conversion fixtures need short clips, impulse position, output length, alias rejection and cancellation before installation. Version 5.0.1 fixes whole-clip delay trimming; verify version-specific behavior. [Rubato APIs and RT considerations](https://docs.rs/rubato/latest/rubato/)
