# Oracle lane C: sample, round-robin and timing (2026-10-23)

Per-note comparison with real Kontakt 8 (`tools/oracle/`). This file is hand-written; `ORACLE_DIFF.md` is
generated by `compare.py` and gets overwritten.

## Tooling

- `capture.py --scenario {base,rr8,velsweep,legato}` and `kontra_render.py --scenario NAME`: both sides play the
  same MIDI (`~/.cache/kontra-native-oracle/scenario-NAME.mid`). Window 9 s for `rr8`.
- `notes.py KONTAKT.wav KONTRA.wav --midi FILE [--matrix]`: per-note attack detection, waveform r at the note's own
  lag, level, and the KONTRA-note x Kontakt-note cross matrix. The MIDI parser round-trips all scenarios (checked).
- Not yet added: keyswitch and release-trigger scenarios (library-specific key numbers), a velocity-layer sweep run,
  and the absolute latency re-run.

## Findings (4 instruments, rr8 scenario, one locked Kontakt session)

- **Horns KS (2 Horns KS, multi-instrument)**: no round-robin start groups (`start_options` empty on all 220 groups).
  KONTRA repeats the same sample for all 8 hits, which is correct for this instrument. Kontakt's 8 hits are
  not identical to each other (zero-lag correlation between hits from -0.6 to +0.65), so Kontakt is not deterministic
  here. The zones carry `sample_start_mod_range = 5120` (about 107 ms at 48 kHz). KONTRA reads that field
  (`library.rs:3576`) but only applies it through a `SampleStart` route (`voice_mod.rs` `offset`), and this instrument
  has none, so KONTRA's start offset is 0. Kontakt's per-hit attack lag is +123..+142 ms against KONTRA's
  first hit at +4 ms. Kontakt's hits sit at r about 0.42 against KONTRA, with Kontakt about 11 dB louder (level lane).
  Verdict: the sample is the same family; the difference is the start-offset randomization and the level/timbre,
  not round robin. The r > 0.9 target does not apply to this material.
- **Vista 3 Violins FFF Overlay**: 6 groups with `round_robin` start (`legreldyn*`, position 1). Kontakt's hit 0 aligns
  at +10 ms (r 0.72), its hits 1..7 at +290..+299 ms (r 0.30..0.51). KONTRA's hits are identical to each other.
  Cause not yet isolated: the RR groups above do not all match key 60, velocity 100 (the first zone covers keys 56-57),
  so the next step is the zone list for key 60 and whether KONTRA's RR counter advances for this instrument.
- **Trumpets Trills, Imperial Brass B**: attacks found on note 0 only (Trills) or a constant +64..+78 ms lag
  (Imperial, level +11 dB). Not analysed beyond this.

## Clock and latency

- The capture clock fix from #517 is in `capture.py` (`t_midi` is taken after the recorder start-up sleep). The
  absolute lags above (+4 ms on note 0 of Horns, +10 ms on note 0 of Vista) are consistent with a small Kontakt
  latency and a correct clock, but the +290 ms on hits 1..7 is not a clock effect (it differs between hits of the
  same note). The absolute re-run with a fixed MIDI onset check is still open.

## Third pass: start-offset law (open; #522 not merged)

**Engine draws (debug trace, Horns KS, 32 notes).** One offset per region per note: each note triggers 16 regions, and the
seed is `now ^ (note << 40) ^ (region << 20)`, so regions draw independently. Draws are spread over 0..5120 frames, as expected
for a uniform draw.

**Direction of the effect (the important finding).** `start_offset` feeds `cursor.skip(start)` (`prepare/selection.rs`), which
moves the playhead *forward* into the sample. A forward skip makes hits start louder and earlier, not later. Measured on the
rendered audio (`/tmp` analysis, `kontra-shared` vs unfixed): hits 1 and 2 are louder in 0–20 ms than the unfixed render, so the
skip is audible, but in the wrong direction. Kontakt is the reverse: its hits are *delayed* 16–98 ms against the unfixed render
(envelope cross-correlation, 5 ms smoothing). The random term should therefore be a note-start delay (attack pushed back by
`offset`), not a sample skip. That is a scheduling change (voice admission at `now + offset`) and is not implemented.

**Per-session variation of Kontakt.** The same Horns material gave delays of 16–98 ms (rr32, velocity 100, 32 hits) and 0–61 ms
(velsplit, 8 hits at velocity 127, 8 at velocity 40). Neither set separates velocity: under velocity-proportional scaling
velocity 40 would top out near 34 ms, but its maximum was 61 ms. The sample sizes are too small to settle a law from one session;
the next step is several sessions of the same scenario, pooled.

**Not checked.** The decompile of the zone getter (0x14084f380) was requested through REA; Ghidra startup on Kontakt8.exe
exceeded its 20-minute deadline, so no pseudocode was read. Sample-rate scaling (44.1k vs 48k: 116 vs 107 ms per 5120 frames) is
not measured separately. Whether routed regions carry the same random term is untested.

**Keyswitch scenario (item 3).** Not run. Keyswitch notes need a per-library key map, which this lane does not have; the
scenario needs that before it can be scored.

## Fourth pass: round robin, start-offset law, keyswitch

**Vista round robin: no counter divergence found.** Checked `native_start.rs` and `lib.rs` (native_cycle) against
`docs/re/KONTAKT_START_CONDITIONS.md` (mode 3 law). Cycle length = max stored position + 1; the index is shared per instrument,
starts at -1 in Kontakt and at 0 in KONTRA (same first match); release events reuse the index. KONTRA stores the getter value
(stored + 1) and matches `tick % len + 1 == position`, which is the same as Kontakt's `index == stored`. Vista key 60, velocity 100
has one round-robin group only on the release layer (group 24 `cl legreldyn1`, 25 zones; groups 25 and 26 are empty and store position
0 each), so the cycle length is 1 and group 24 fires on every note-off in both engines. The rr8 Vista mismatch is therefore not a
counter problem. Remaining gap: KONTRA excludes keyswitch notes from the increment; Kontakt's note callback may count them. Not verified,
needs a keyswitch capture (see below). No unit test added, because no divergence was found.

**Start-offset law, per session (rr32, 32 Horns hits each, `kontakt` side, KS vs candidate law over [0, 5120) frames):**

| session | mean delay ms | KS uniform | KS u^1.5 |
|---|---:|---:|---:|
| s1 | 57 | 0.194 | 0.305 |
| s2 | 52 | 0.200 | 0.322 |
| s3 | 26 | 0.491 | 0.357 |

The 96-hit pooled fit favours u^1.5 (KS 0.147 vs 0.21), but only because s3 is low. s1 and s2 fit uniform, and s3 fits
neither (critical KS at n=32, alpha 0.05 is about 0.24). Session-to-session spread is larger than the difference between the
two laws, so the law is not established. **#522 keeps the uniform draw.** A future law needs more sessions of the same scenario
and a check on whether velocity or sample rate moves the mean.
