# Oracle lane C: sample, round-robin and timing (2026-10-23)

Per-note comparison with real Kontakt 8 (`tools/oracle/`). This file is hand-written; `ORACLE_DIFF.md` is
generated by `compare.py` and gets overwritten.

## Tooling

- `capture.py --scenario {base,rr8,velsweep,legato}` and `kontra_render.py --scenario NAME`: both sides play the
  same MIDI (`~/.cache/kontra-native-oracle/scenario-NAME.mid`). Window 9 s for `rr8`.
- `notes.py KONTAKT.wav KONTRA.wav --midi FILE [--matrix]`: per-note attack detection, waveform r at the note's own
  lag, level, and the KONTRA-note x Kontakt-note cross matrix. The MIDI parser round-trips all scenarios (checked).
- Not yet added: keyswitch and release-trigger scenarios (library-specific key numbers), a velocity-layer sweep run,
  and the absolute latency re-run.

## Findings (4 instruments, rr8 scenario, one locked Kontakt session)

- **Horns KS (2 Horns KS, multi-instrument)**: no round-robin start groups (`start_options` empty on all 220 groups).
  KONTRA repeats the same sample for all 8 hits, which is correct for this instrument. Kontakt's 8 hits are
  not identical to each other (zero-lag correlation between hits from -0.6 to +0.65), so Kontakt is not deterministic
  here. The zones carry `sample_start_mod_range = 5120` (about 107 ms at 48 kHz). KONTRA reads that field
  (`library.rs:3576`) but only applies it through a `SampleStart` route (`voice_mod.rs` `offset`), and this instrument
  has none, so KONTRA's start offset is 0. Kontakt's per-hit attack lag is +123..+142 ms against KONTRA's
  first hit at +4 ms. Kontakt's hits sit at r about 0.42 against KONTRA, with Kontakt about 11 dB louder (level lane).
  Verdict: the sample is the same family; the difference is the start-offset randomization and the level/timbre,
  not round robin. The r > 0.9 target does not apply to this material.
- **Vista 3 Violins FFF Overlay**: 6 groups with `round_robin` start (`legreldyn*`, position 1). Kontakt's hit 0 aligns
  at +10 ms (r 0.72), its hits 1..7 at +290..+299 ms (r 0.30..0.51). KONTRA's hits are identical to each other.
  Cause not yet isolated: the RR groups above do not all match key 60, velocity 100 (the first zone covers keys 56-57),
  so the next step is the zone list for key 60 and whether KONTRA's RR counter advances for this instrument.
- **Trumpets Trills, Imperial Brass B**: attacks found on note 0 only (Trills) or a constant +64..+78 ms lag
  (Imperial, level +11 dB). Not analysed beyond this.

## Clock and latency

- The capture clock fix from #517 is in `capture.py` (`t_midi` is taken after the recorder start-up sleep). The
  absolute lags above (+4 ms on note 0 of Horns, +10 ms on note 0 of Vista) are consistent with a small Kontakt
  latency and a correct clock, but the +290 ms on hits 1..7 is not a clock effect (it differs between hits of the
  same note). The absolute re-run with a fixed MIDI onset check is still open.

## Update: second pass (not merged as a fix)

**Corrections to the first pass.** The Vista "+290 ms on hits 1..7" was an artifact. Vista is near-silent at key 60
velocity 100 on both sides (about -62 dB peak; KONTRA -61 dB), and the attack detector fired on noise. Vista's
release-trigger zones (group 28 `cl reldyn1`, `hardrel` samples, `sample_start_mod_range` 26058) also fire on every
note-off, which contaminates neighbouring hits in the rr8 scenario. Vista round robin is not established by this data.

**Start randomisation (Horns KS).** Kontakt's Horns onsets over 32 hits spread 50..140 ms (10 ms steps, median 80 ms).
KONTRA's onset is fixed at 30 ms. Horns has no `playPos` route (checked with `examples/sample_start_routes.rs`), so
the offset cannot come from a route. Zones carry `sample_start_mod_range` 5120 frames. The engine change in this branch
draws a uniform per-voice offset in [0, range) when a region has a range and no SampleStart route
(`voice_mod.rs` `random_start` / `random_offset`; the two predictors return unknown for such regions). The unit
test passes. **Not verified:** the fixed render's per-hit delay against the unfixed render is bimodal, about 0..20 ms
or 140..196 ms (r about 0.5), and 196 ms exceeds the 107 ms range. The law (units, distribution, velocity scaling,
whether routed regions get the same random term) is not yet pinned down. Next: dump raw offsets from the engine for
32 voices, and check the frame-unit conversion.
