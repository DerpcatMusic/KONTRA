# Attack preload and first-tail streaming evidence

Three owned Analog Strings snapshots now produce nonzero audio through the real V2 loader, script activation/effect host and renderer with bounded resident heads. This does **not** establish dropout-free playback or preset-switch equivalence: Harmonics retained eight first-tail underruns in one run and one in a separate fresh-owner worker-audit run. The 300-voice / 1% KONTRA-meter target remains open; this investigation is distinct from [CPU_EVIDENCE.md](CPU_EVIDENCE.md).

## Why the reported 7.8 GB request retained no heads

The request was optional sample-start modulation coverage, not mandatory full-resident audio. Actual pre-fix V2 Auto geometry for all three snapshots had 23,595 physical assets, 95,624 zones, no aliases, no mandatory-full assets and no pinned wavetable assets. Fully decoded sources would occupy 50,156,846,256 bytes; the independent streamed page pool was 100,663,296 bytes.

These are merged per-asset request geometry before decode. Two bytes per source frame is a lower packing bound, not actual resident cost. The full offset union therefore required at least 7.79–7.82 GB even before decoding. The previous typed-capacity fallback retained mandatory sources only; these snapshots had none, so the accepted fallback had zero heads. It did not allocate 7.8 GB.

The offset-free Gates request fits even at eight bytes/frame (265,422,824 < 268,435,456 bytes), as does Punch (261,128,088). Storage-latency-derived horizons vary between loads, however: a later Gates load requested 1,763 frames and again exceeded the quota even without offsets. Arbitrary script offsets and all modulation offsets cannot be assumed warm.

`573f7799c` adds opt-in numeric `stream_preload_geometry` records; `9363f43cb` tries complete authored base attacks after a typed offset-coverage quota failure. Required-full and pinned wavetable sources retain their requirements. Original offset requests remain authoritative for full-coverage reporting and explicit reload.

`c417f76fc` additionally selects a shorter uniform attack horizon when complete base attacks exceed the quota. The binary search evaluates only metadata and a conservative eight bytes/frame bound against available shared physical quota, preserving interpolation guards, reverse endpoints and disjoint starts. It performs one final preparation after the search. Packing/publication still pass exact shared-quota admission; mandatory or minimum-anchor failure stays a typed error with no partial publication. `StreamStartup.selected_anchor_head_frames` and anchor coverage are separate from the original requested onset coverage. The quota remains 256 MiB.

## Retained first-tail fault and worker attribution

In the sounding three-snapshot run, Harmonics' eight warm-admitted voices from source zones 46474–46481 first starved during block 1. Their current reads were around absolute source frames 1,616/1,657, page 0 remained `Pending`, and those ranges were no longer covered by resident heads. Block-1 callback time was about 698 microseconds versus a 5,333-microsecond audio span. By block 2 all 14 current demands were ready. This identifies source starvation, not an observed callback overrun.

A separately approved fresh-owner worker-audit repeat also sounded from output offset zero, but retained **one** underrun. It loaded all 39,420 original base attacks in 217,963,092 bytes. The missed voice was source zone 46481, page 0, at block 4 / source position 2,276. Its job was queued at engine frame 96,512; queue wait was 26 microseconds, open took 9,362 microseconds wall / 36 microseconds thread CPU, and read/decode took 907 microseconds wall / 22 microseconds CPU.

The same asset's page-1 and page-2 jobs launched on other workers and each reopened it (9,342/9,323 microseconds wall). Across four workers: 309 jobs, 46 opens, zero decode failures, zero reply backpressure, zero reader evictions and zero omitted probes; retained-reader peaks were only 325–350 KB per 2 MiB worker quota. Queue maxima were 5.7–6.24 ms and the longest job 21.24 ms. Aggregate worker CPU was about 9.65 ms across the entire receipt. This points to off-CPU/storage/scheduling delays and duplicate cross-worker opens, not expensive decoding alone. The repeat overlapped external compilation and a separate UI load; it is not a controlled before/after dropout comparison.

Two hypotheses remain unpromoted:

- Linear demand assigns the outer page fragment's deadline before removing resident head ranges. Partial page-0 tails can therefore receive the same immediate priority as genuinely cold page-0 reads. Direction-correct first-use at the actual uncovered edge could preserve urgency ordering.
- Per-worker reader caches can open one asset independently for concurrent pages despite ample free cache. Bounded source locality may remove repeated opens, but it cannot guarantee the first open meets a short runway. Near-edge start offsets may need an explicit minimum runway/priming rule rather than immediate warm admission.

No production scheduling or onset-holding change is justified solely by these two contended receipts. Exact source-start/pitch metadata, worker ordering oracles, independent fresh-owner repeats and boundary tests are needed before promotion.

## Quota-selected constant-onset preparation

The next implementation supplements base attacks with the proved positive, non-loop Constant onset windows. It first tries the unchanged complete possible-offset request. Only its typed payload-capacity failure permits alternatives: base-plus-hint windows at the requested horizon, original full base attacks, shorter base-plus-hint anchors, then shorter base anchors. Required full-resident sources and pinned wavetable ranges retain their original requirements in every candidate. An optional hint that cannot fit must not discard a base anchor that can fit. A source/metadata error or cancellation does not authorize a cold-success retry.

The shorter-horizon search evaluates metadata with a conservative eight-byte/frame bound; it does not decode each trial. Each attempted candidate still requires exact lossless packed admission against the same physical payload quota, including staged/current/retired leases. Failed candidates publish no partial heads. This introduces no audio-thread source I/O, allocation, blocking or added onset holding. It can add control-side decode work when a speculative hinted candidate exceeds its exact packing quota; no faster-load claim is made. Opt-in `stream_preload_attempt` records distinguish requested geometry, candidate elapsed time and successfully admitted physical payload. Requested frames are not decoded-byte counters.

Requested hints and actually selected hints are separate `StreamStartup` fields, including their source-frame unions, complete-range counts and selected output horizon. `Pcm::resident_covered_frames` counts actual partial intersections with the current immutable resident snapshot; a partial requested window is not reported as fully covered. Aliases are deduplicated by immutable physical `AssetId`, while separately constructed revisions remain distinct. Looped, wavetable, dependent and arbitrary scripted offsets retain their original fallback semantics and are not certified by selected-hint readiness.

Optimized `ci` authored validation passed two coverage/allocation tests, three existing actual-start query tests and eight hinted-policy tests. These cover exact float payload boundaries, one/four preparation workers, shortened requested-versus-selected coverage, minimum hinted failure preserving nonempty base attacks, source/cancellation atomicity, required-full/pinned preservation, alias unions, failed reload retention, and bitwise PCM at offset 745 for forward/reverse traversal, steps 1/1.78125/16 and host partitions 1/7/64/128. ## Conservative loop-prefix and restore authority

The follow-up permits a positive Constant onset on a forward looped source only when the **prepared cursor** proves its complete initial interpolation window stays before the first active loop transition/crossfade. `Prepared::constant_start_forward_prefix` uses the same `skip` and `linear_reach` laws as runtime source demand. It rejects saved loop controls, any LoopStart/LoopLength route, reverse traversal, finite exits, indexed multi-loop or non-unity loop-slot geometry, crossing windows and invalid steps. The opaque descriptor binds an immutable physical AssetId and compact cursor template; it retains neither PCM nor a plan. Its footprint is paid only for eligible loop-prefix zones, off audio. Existing non-loop hints retain their original geometry. No native loop/modulation law is inferred from these tests.

Eligibility is fixed at the original requested horizon, and later metadata trials can only reduce that horizon. A zero-frame trial still requests its interpolation guards; it cannot later expand into a larger requested authority. Required-full and pinned source requirements, exact shared packed quota, original complete possible-offset requests and base-attack alternatives are unchanged. Loop controls, transitions, arbitrary script offsets and unproved future pitch changes remain outside this static hint promise. The eight source-bound Harmonics geometries have a conservative step bound 2.24492704 and a 515-frame physical window approximately `[637, 2010)`, well before their earliest 89,050-frame loop entry. This covers their prior missing windows geometrically; only a new frozen musical witness can establish actual admission and dropout behavior.

Restore recipes now retain the selected physical range table rather than expanding admitted shorter heads back to the original oversized possible-offset request. The same immutable per-source table feeds the KSP residency loader, automatic cold reloader and explicit Streamer reload. Each source is tagged **Admitted** or **DeferredRequested**. Lazy/mandatory-only startup and an empty optional selection with a nonempty original request retain the original deferred request; later quota failure remains observable. Mandatory full PCM and pinned ranges keep their original authority. Original requested coverage remains separately reported, and explicit expanded-request failure tests still exercise the original table. This changes neither the core rule for an already-resident partial head nor source-revision identity.

The new alias-trim reproducer first failed: two references to one physical sample caused 256 bytes of unnecessary eviction even though the actual two-source payload equaled its 512-byte limit. Trim now deduplicates immutable AssetIds before both total-byte and idle-candidate accounting. All these scans, recipe allocations and preparation remain control/worker work; no extra render-path query, wait, allocation or I/O is introduced.
