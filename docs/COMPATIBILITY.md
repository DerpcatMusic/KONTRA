# Compatibility implementation checklist

This checklist describes implementation boundaries, not a guarantee that an imported instrument sounds or behaves like Kontakt. The current symbol-based inventory is in [Feature status](FEATURES.md); the broad summary remains in the [README](../README.md). No area here is certified as complete.

## Source, validation and released builds

Reviewed development source: `8e43d00`, 2026-10-02. The 0.3.23 source passed 443 library tests and 83 playback tests in public CI. The subsequent group dynamics/transient processing, group start-record preservation, periodic audio diagnostics and rack header changes still await their combined validation gates. A source change, an isolated passing test and a published nightly are separate milestones. Check a downloaded artifact's build identity and `release-manifest.json`; this document does not assert that development changes are already available in that artifact.

Historical CI results above do not validate the current working tree. The 2026-10-04 core pass separates physical MIDI, raw library controls, instrument state and note owners; production builds have passed, while new musical scenarios remain staged and unrun as requested. See [the retained roadmap](CORE_MIDI_REFACTOR.md) and [concrete scenario ledger](CORE_PERFORMANCE_PROOF.md#staged-musical-verification--2026-10-04-unrun).

- **Implemented, partial:** a code path exists; its stated limits still apply.
- **Integrated, validation pending:** present in the reviewed development source; the combined validation/release gate remains open.
- **Candidate, validation pending:** isolated work awaiting integration or required checks; unavailable in the reviewed source.
- **Open:** unsupported semantics, an unverified interpretation, or missing reference evidence.

Targeted checks validate their exercised behavior. They do not establish arbitrary file compatibility, every script action, live-host deadlines or Kontakt sound equivalence.

## Recorded player behavior

Instrument and per-voice gain/pan changes now follow retained 5 ms sample clocks,
including retargeting and the native Amplifier position. Complete real-time PCM
performances exercise 20 notes, release, pedals, exact owner expressions, pitch
reuse, host automation, silence and unique note ends. Native wrapper execution,
hardware deadline performance and arbitrary-library equivalence remain separate
verification. CPU-driven release shedding and heuristic effect sleeping are removed;
quiet signals, tails and filtered mute/unmute state retain ordinary processing. See [performance evidence](CORE_PERFORMANCE_PROOF.md).

Applied controller/expression state and physical parameter transactions have one
owner in `engine/midi_state.rs`; voices read captured physical controller rows.
A separate raw delivered-channel bank feeds native group predicates. Physical
reset cancellation remains isolated when library routing merges channels.
Saved controller defaults also retain accepted-source availability separately
from numeric caches. Input replacement clears old negotiation and retains exact
NOTE_END identities for retry; its new PCM scenarios remain staged and unrun.

Legacy `TIMER_MS,-1` is accepted as a disabled timer, using the existing zero-value
scheduler policy. This is compatibility with observed initialization scripts;
NI's current manual documents zero disabling, not this legacy sentinel.

UI instrument recognition and auto-alignment accept ordinary and Windows verbatim
representations of the same drive/UNC path. Program and replacement guards remain
in place. This comparison does not resolve relative paths, symlinks or case aliases.

Before a pending behavior becomes a compatibility claim:

- [ ] Reproduce its causal record, service call or authored interaction; distinguish unsupported semantics from missing or malformed input.
- [ ] Fix the shared importer/runtime/DSP path and retain honest failures on unsupported inputs.
- [ ] Run a focused check that fails without the change, including stale-source/boundary handling where applicable.
- [ ] Check real audio/state/control results, rather than only parsing, successful catalog enumeration or warning removal.
- [ ] Verify bounded work and zero render-thread heap operations for changed callback/processing paths.
