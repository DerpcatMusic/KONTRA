# Shared note expression

The shared engine keeps note identity, expression identity, physical source state and per-attack processing ownership separate. Two notes on the same key can use the same immutable sample storage while retaining independent cursors, filter histories and expression values. Script-generated children can follow their parent's pitch, pressure, timbre and bend while retaining their own gain, pan and release policy.

An optional `SignalParameter.expression` maps the retained note's full-resolution pressure or timbre to a factor on its ordinary base parameter. Gain supports a nonnegative linear factor; OnePole cutoff supports an octave factor. Global control edits, ramps, snapshots and recalls continue to own the base. They do not replace either note's expression value. The compiled mapping and every combination of its endpoint and base-control domain are validated before publication, including the actual sample-rate cutoff limit.

Shared stages retain one filter history per processing owner and channel. Expression changes do not retrigger sources, clone plans, reset histories or mutate another note's filter. Missing expression bindings preserve the existing signal. Explicit signal nodes execute at their authored graph position, before a nonempty legacy scope chain; this is not an automatic post-chain effect injector.

Existing stereo source Tone remains after the authored voice chain on the main outlet. Its per-note state is distinct from shared bus effects and existing earlier send/tap positions. Public loader default-Tone tests and the product's adaptive Kontakt mapping are different recipes and must be evaluated as such.

The MIDI adapter supports explicitly configured lower or upper MPE zones. Host-note admission retains initial tuning separately from member/manager bends and part transpose. Native host expressions and terminal events use captured note identities, including pending aligned notes, rather than a Part's later input-port or channel setting. Incoming MIDI1 MCM/RPN6 messages configure Lower/Upper membership, arbitrate overlaps and disable zones without changing the selected instrument zone. A receiver instance selects one zone; it does not claim two simultaneous independent zone instruments. Manager0 and15 parameter selection is accepted before the selected-zone filter, while the product's input Part/port/channel admission remains authoritative. CC38 does not change MCM membership. Addressed-zone pitch sensitivity resets to2/48 semitones; later RPN0 changes remain separate. Channel-role changes stop affected input owners and reset their physical controllers without overwriting other channels' CC1/CC11 or reviving older delayed writes.

Controller state has an explicit global Performance domain and bounded physical domains keyed by Performance, protocol, port, group and channel. Global API edits remain global; MIDI/controller callback reads and source modulation use the captured physical address. Notes retain immutable onset snapshots. Delayed callbacks retain each target's reset revision across waits and generation changes. Physical-bank capacity is checked upfront; an exhausted bank refuses before input/callback publication.

Automatic MCM is not full MIDI2 receiver certification. The existing product wire adapter still maps MIDI1 and MIDI2 channel voice traffic into a common internal MIDI1 address/gesture domain; splitting those identities end to end is the next implementation slice. Registered/assignable MIDI2 per-note controllers, per-note management and most registered/assignable channel controls remain unsupported and must be reported. Native host note-ID expression is a separate represented path. A parsed packet or nonzero output is not evidence that all its semantics were implemented.

The resident channel graph and these optional enhancement mappings are shared engine capabilities. They do not establish native sampler DSP parity, activate every importer recipe, make a shared bus per-note, or establish actual VWinds admission. Streamed wide-source resource budgets and unresolved native layout/scope laws remain separate work.
