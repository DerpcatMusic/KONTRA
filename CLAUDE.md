## Reading the reference binaries

Kontakt is decompiled once, into a private cache outside the repo
(`/data/dev/workspace/re-cache/<binary>-<version>-<sha8>/`). Read it with
`re-lookup` (`tools/re/re-lookup` in the monorepo) before you run `kuna`, Ghidra
or the `rea` MCP on Kontakt:

- `re-lookup fn <addr|name>`: the pseudocode. A miss decompiles that one
  function and adds it to the cache, so decompile through `re-lookup`, not by hand.
- `re-lookup xrefs-to|xrefs-from <addr>`, `re-lookup grep <regex>`,
  `re-lookup str <regex>`, `re-lookup vt <class>`, `re-lookup info`.

Never commit pseudocode or disassembly from it: this project is mirrored publicly.
Describe the behaviour instead and cite the store as `[ref]` (below).

**Reverse-engineering material never enters this tree.** KONTRA is mirrored
publicly. Disassembly, decompiler output (`FUN_`/`DAT_`/`LAB_` names,
`undefinedN`, `iVarN`, pointer-cast pseudocode), vtable/RTTI dumps, binary
image addresses (`0x14…`), citations of decompiled `.c` files and
line-by-line paraphrases of vendor functions live only in the private RE store
(`/data/dev/workspace/re-cache/`; moved KONTRA notes keep their relative paths
under `kontra-notes/`). Public docs and comments state the behaviour in our own words
and maths ("cutoff = 20·2^(x·10) Hz, measured") plus oracle measurements; a
citation into the private store is written `[ref]`. Scripts that drive the
vendor binary at addresses (emulators, oracle drivers, Ghidra scripts) live in
the private store too. `python3 tools/sync-stack.py --check` fails on any of these
markers; the only exemption is ni-file's `native_schema/` and its generator,
listed by exact path in `RE_MARKER_ALLOWED`, and that list may only shrink.

## The parity board

`docs/PARITY.md` and `docs/PARITY.html` are generated by `tools/parity-board.py` and
never committed (gitignored). A PR changes evidence and, when needed, the snapshots in
`docs/parity/snapshots/`, keeping each snapshot's rows in byte order (`LC_ALL=C sort -u`
below the header) so independent additions merge. `tools/parity-board.py --check`
(run by `sync-stack --check`) fails on a malformed or unsorted snapshot. The monorepo
mirror job generates the board for the public site.

## UI (the editor's chrome, `crates/app/ui`)

Spec: [docs/specs/ui-lift.md](docs/specs/ui-lift.md). Every UI PR keeps these:

1. **Intrinsic UI.** No hardcoded sizes unless truly necessary; a container's
   minimum comes from its content. Lists of long names ellipsize and show the
   full name on hover. A resized window reflows (the editor runs at the
   interface scale, never zoomed to fit a design size).
2. **Spacing tokens.** Spacing, gaps, padding, corners, stroke widths and type
   come from `kontra_ui::theme` (`HAIR`, `NOTCH`, `MARK`, `TIGHT`, `SPACE`,
   `INSET`, `TEXT`, `SMALL`, `CONTROL`). A token times a factor is fine; a bare
   pixel count at a call site fails `crates/app/ui/tests/tokens.rs`. Missing a
   token? Add it to the theme. MUI changes stay generic.
3. **Measure everything.** Shots at the minimum window, the default and ~1.8×
   the default, before and after (`crates/app/ui/examples/app_shot.rs`), with
   the numbers that changed. Look at the PNGs before calling it done.
