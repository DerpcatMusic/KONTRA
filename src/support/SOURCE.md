The crash recovery, native OS collectors, redactor, report summary limits and acknowledgement protocol are adapted from owner-maintained BUFFR commit fd2fdba92f3f71cee24c0c72a39aa190fc9ee414:

- crates/buffr-engine/src/support/crash.rs
- crates/buffr-engine/src/support/platform.rs
- crates/buffr-engine/src/support/report.rs
- crates/buffr-engine/src/support.rs
- vendor/derpcat-flight-recorder
- crates/buffr-durable-file

BUFFR declares ISC in its workspace manifest. The ISC notice is retained in LICENSE-BUFFR and in both vendored crates; the recorder retains its original license and README. These files remain ISC; KONTRA's repository license does not replace those notices.

KONTRA differences: its existing build identity and diagnostics worker supply the metadata and journal events; proprietary source excerpts remain local; numbered UTF-8 chunks preserve events beyond the recorder's detail limit; each pending incident retains its captured report until a matching SHA-256 acknowledgement. Complete journal and native originals are archived through private durable publication and remain locally after acknowledgement; automatic uploads contain sanitized, bounded views, not those raw files. The initial marker is written before system metadata subprocesses. Legacy macOS .crash files are also recognized by exact PID. Failed submissions persist a local receipt/error and become eligible for retry on a subsequent load, including delayed OS evidence. BUFFR's host-wide Rust panic hook and abort-on-cleanup-failure are deliberately omitted in the plugin; no native crash handler is installed. Native stacks therefore depend on accessible OS/host artifacts. Captured panic markers remain readable for recovery, but this integration does not invent a process-global capture hook.

Metadata collection runs after the registration acknowledgement; macOS commands share the reporter's shutdown cancellation flag. Cancellation can leave the module's cached metadata incomplete. Each incident has its own durable, private queue file; acknowledging one ID cannot remove another incident. Registration inspects bounded batches using retained cursors, prioritizes confirmed incidents in the selected batch and privately defers unconfirmed evidence for later native confirmation. Legacy pending.json migration preserves a complete private raw original and manifest before publishing keyed entries; failure or cancellation retains the legacy source. An OS-confirmed host crash establishes a crash while KONTRA was loaded, not fault ownership; report text keeps attribution unknown unless the exception and stack establish it.

Delivery results use the existing diagnostics view with a readable reason and separate report ID; an optional service issue URL is accepted only for the public DerpcatMusic/KONTRA issues path. A bounded, whitelisted local receipt is replayed on the reporter worker after startup acknowledgement. Linux native confirmation additionally requires the recorded executable, not just PID/time. Native text redaction recognizes quoted paths, drive-letter paths using either separator, and UNC assignments while preserving exception/frame symbols.

The owned vendored additions are `buffr-durable-file::publish_private_streaming` for durable atomic publication without buffering an entire original, and `derpcat-flight-recorder::JournalCapture` for bounded journal capture. Uploads retain up to 128 startup and 2,048 recent records, with recorded drops, sequence gaps, omitted slots, original size and BLAKE3 hash. The complete original remains in local `crash-reports/originals`; these archives have no automatic age/size pruning. Bounded native views label retained prefix/suffix bytes and omissions. Oversized or unsupported evidence is not partially parsed into crash confirmation. Transport enforces the service's JSON size cap before network delivery.

Manual export is a separate privacy boundary. `crash-evidence/` contains exact archived private originals and saved incident/delivery records, with a per-file manifest marking missing, active or incomplete sources. These copies are unredacted and may contain sensitive native fields, local paths and recorded fault context. Structured-log redaction does not alter them. Review them before sharing. Manual export neither searches OS crash directories nor copies binary process dumps; automatic uploads exclude raw archives and proprietary source excerpts.

The support-service backend is a separate, pending integration: its intended contract stores the full submitted report privately in R2, applies server-side redaction, expires that server copy after 30 days and publishes only a metadata summary. This does not mean the complete unredacted local originals are uploaded. Source-level and authored-fixture checks do not establish a production host-crash → private storage → public issue roundtrip. An OS-confirmed crash establishes that KONTRA was loaded, not that it caused the crash; unclean exits without matching native evidence remain unconfirmed.
