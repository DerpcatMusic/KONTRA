Kontakto replacement review — 2026-10-01, commit bb7dca9

**Keep the engine. Finish compatibility and prove it.** This is a substantial native Linux sampler with real playback scripting, streaming, modulation, effects, editing overrides, MPE routing and multi-output support. It is not yet a demonstrated complete replacement for Kontakt. The main danger is accepting “it loads and makes sound” as evidence that a commercial instrument behaves correctly.

This review traces the repository graph, importer, sample bank, streaming workers, voice renderer, script compiler/runtime/services, plugin callback, state and routing. It includes fresh builds, tests and short local benchmarks. It does not include Kontakt reference renders, an exhaustive current audit of every preset, GUI profiling, or validation inside a real DAW. No implementation was changed.

**The documentation is materially stale.** README.md and audits/README.md still say playback callbacks and DSP are unimplemented; the current engine and tests implement both, partially. The old missing-resource counts were affected by an NTFS driver problem. audits/NTFS.md records the confirmed ntfs3 fix, and this review independently observed the current ntfs3 mount. audits/LIBRARIES.md reports successful representative loads from eight Kontakt libraries, including scripts and DSP. Its test chooses one heavy patch per library and plays a few notes; it does not certify the other presets, every articulation or sonic parity. The main audit generator also counts initialization results rather than complete runtime behavior. Regenerate the compatibility inventory around actual capabilities and preserve dated historical reports as historical evidence.

**Existing work worth preserving:**

- Off-thread import, decoding and script initialization; bounded queues transfer banks, scripts and DSP to the callback, with disposal sent back to the worker. See src/plugin.rs:1697 and src/plugin.rs:920.
- Shared resident sample spans and sources across instances; interned immutable zone/map arrays; persistent parsed-instrument caching and shared compiled scripts. See src/engine/bank.rs:192, src/engine/bank.rs:260, src/cache.rs:46 and src/ksp/runtime.rs:23.
- AVX2 paths, compact PCM storage, shared interpolation/filter rendering, paused inaudible streaming, idle effect sleeping, and overload tail shedding. See src/audio.rs:208, src/engine/mod.rs:1397, src/engine/voice.rs:1042, src/fx/processor.rs:81 and src/engine/mod.rs:1365.
- Playback tests compare RAM and streaming, shared and individual rendering, MIDI timing, release behavior, routing and several allocation-sensitive paths. The KspEngine boundary has production, logging and benchmark implementations; it is useful, not a speculative interface to delete.

Short runs, caches warmed by earlier reads and ordinary desktop scheduling limit these numbers. Some benchmarks overlapped compilation/tests or other benchmark processes. “Late blocks” are paced deadline misses, not necessarily sample-stream underruns. Zero reported dropouts does not establish spare capacity at 32/64-frame buffers. The one-part run also had a 2.844 ms wall-time outlier during the tail phase; maximum latency deserves attention even when average CPU is low. The harness's after phase still contains releasing voices, so it is not a true all-tails-finished idle measurement.

**Performance priorities, ordered by expected practical value:**

1. **Profile and reduce per-part/background overhead before further mixer micro-optimization.** Four streaming threads are created for every streaming bank (src/engine/stream.rs:35 and :368): a full rack can create 64, multiplied again by plugin instances. Workers scan their stripe and wake every millisecond while active (src/engine/stream.rs:457). Rings reserve 64 MiB per streaming bank, although untouched/reclaimed pages make physical RSS smaller. The sixteen-copy experiment makes heap profiling of bank metadata, mutable group state, script arrays/events, stream cursors and allocator arenas worthwhile. Preserve independent mutable script/voice state; share immutable definitions and decoded blocks where profiling demonstrates reuse. First cap background concurrency across loaded parts; a shared streaming pool is justified if scheduling/wakeups are the measured bottleneck.
2. **Reuse disk work across voices and instances.** Each stream cursor opens its own SampleReader (src/engine/stream.rs:503); Source opens the underlying file for that reader (src/audio.rs:715). Repeated archive opens and repeated NCW block decoding are candidates for shared archive handles with positional reads and a bounded decoded-block cache. Measure open counts, read amplification, cache hit rate, disk latency and CPU first. Avoid eagerly extracting or converting entire libraries.
3. **Make script execution budgets fit the real callback deadline.** BLOCK_FUEL is two million VM instructions per runtime and CALLBACK_FUEL five million (src/ksp/runtime.rs:54). Sixteen runtimes each have their own allowance; none of these caps proves a callback will finish within a small audio buffer. Measure the worst legal script/event bursts and set deterministic sample-rate/block-aware budgets with an explicit policy for deferred work. Keep event ordering and sample timestamps correct. Do not move all playback callbacks to a generic worker and introduce nondeterministic timing.
4. **Finish the allocation guarantee.** Existing tests are meaningful, but one deliberately warms string buffers before counting allocations (tests/playback.rs:1599). StrStack grows on demand (src/ksp/vm.rs:131), property vectors and strings grow during callbacks (src/ksp/ui.rs:41), menu operations allocate (src/ksp/calls.rs:915), and save_array clones/stores values (src/ksp/calls.rs:306). Pre-size supported callback data off-thread, impose explicit bounds and queue real asynchronous services to workers. Test first-use callback paths as well as steady state, including deallocations.
5. **Improve initial load and cancellation.** Load.run processes rack parts serially; its parallel helper creates scoped worker threads sized to available CPUs for each operation (src/engine/bank.rs:1164). A new selection is checked after the expensive import/script/bank work, rather than cancelling those phases early. Add cancellation between expensive phases and bounded storage-aware loader concurrency. Reuse the existing caches. An archive/sample metadata or preload cache should be added only for measured repeated work.
6. **Correct cache dependency invalidation.** The disk instrument stamp includes importer code, NKI path, size, timestamp and program (src/cache.rs:84), but not referenced archives, loose samples, resource containers or NICNT metadata. Cached resolved paths, warnings and loaded IRs can become stale when those dependencies change. The live shared-program map also keys only on canonical path/program (src/import.rs:185). Add dependency stamps appropriate to what each cache stores; do not hash every gigabyte on each load.
7. **Measure sustainable capacity.** Extend the existing harness to 32/64/128/512 frames, 44.1/48/96 kHz, 1/4/16 parts, multiple plugin instances, cold/warm files, active editing, CC floods, dense chords, articulation changes, loops, release tails and offline bounce. Record p99.9/max callback times, missed deadlines, underruns, dropped commands, steals, audible/total voices, RSS and background CPU. The current microbenchmark extrapolates voices/core from the best of seven runs; it is useful for regressions, not a capacity guarantee.

GPU audio, a language/framework rewrite and blanket per-voice parallelism are not supported by the present evidence. Small duplicate-core benchmarks already run cheaply. The likely larger gains are template memory, repeated decoding, worker scheduling, loading and worst-case callback safety. No unmeasured speedup is promised.

**“Any library, no matter what” cannot be an honest guarantee.** There are separate problems: parsing a container/version; accessing legitimately available sample data; implementing all native engine and script behavior; reproducing the UI/state; and matching the sound. Future formats, unknown ciphers, unavailable authorization metadata and genuinely absent bytes remain limits. The local metadata scheme is not a universal key. The library inventory also correctly rejects Ample Sound, UVI, Toontrack and IK containers: these are separate proprietary runtimes/formats, not Kontakt instruments. Supporting those would require distinct adapters or cooperation, not a more permissive NKI parser.

A useful promise is a published, versioned compatibility matrix with separate results for metadata import, reference resolution, sample decoding, script initialization, exercised callbacks, articulation behavior, controls/state and Kontakt comparison. Label exact support, approximate support, degraded playback and unsupported cases distinctly. Silent no-ops must not contribute to an “exactly supported” result. Rank implementation work by broken behavior across supported libraries, not just static symbol frequency, which includes dormant branches and default/bypassed effects.

Extend the existing articulation editor, MPE, sound overrides, routing and experimental auto-align with proven recall and host behavior. Provide named stable automation macros and a portable, versioned native preset/manifest so newly authored content does not inherit proprietary container fragility. ## Implementation and verification, 2026-10-01

The review above describes `bb7dca9` before changes. Priorities 1–6 are now implemented on `codex/performance-hardening`, still based on that commit. The separate `87a18dc` SIMD/PGO/library-browser revision was compiled and benchmarked in an isolated detached checkout; it has not been merged or deployed by this work.

| Priority | Implemented behavior | Runnable regression |
|---|---|---|
| 1. Background/per-part overhead | Four shared streaming workers per loaded plugin module, fair rotation and urgent reads first; workers stop when the last bank retires. Numeric script persistence/UI arrays use compact typed vectors rather than one enum per element. | `banks_share_workers_and_retire_them`, compact/legacy persistence checks, host rack benchmark |
| 2. Repeated disk/codec work | Archive handles use positional reads with independent cursors. Each worker retains at most 64 readers and 128 decoded 2,048-frame blocks (2 MiB of frame data); cache identities retain their sources. | Independent-reader and decoder reuse/cache-bound/end-of-file checks; streaming/RAM equality |
| 3. Callback budget | A host block's fuel survives MIDI/render splits. Live work scales with frames, rate and scripted-part count, with a 40% per-rack script time allowance. Straight-line statement checkpoints supplement loop/call checkpoints. Large synchronous array operations reject work beyond the live budget with diagnostics. Offline retains the larger deterministic allowance. | `managed_audio_budget_is_shared_by_segments_and_rejects_large_sync_arrays` |
| 4. First-use allocation | Loader prepares bounded string, menu, PGS, keyboard, listener and save/load-array storage. Callback capacity failures produce explicit diagnostics. The first-use regression counts allocations **and frees**, without warming the callback. | `first_use_script_services_do_not_allocate_or_free`, `oversized_callback_text_faults_without_allocating` |
| 5. Loading/cancellation | Global sample-decode phases use at most four workers. Superseded selections, including effective rack/part streaming changes, cancel between stages and decode chunks; canceled loads cannot report completion or publish a partial bank. | `canceled_load_does_not_publish_a_partial_bank_or_completion` |
| 6. Cache dependencies | Parsed disk/live caches include sample/archive, NICNT, resources, impulse and search-directory metadata. Source/resident-span identities include source versions; replacing a sample while its old bank lives does not reuse stale preload data. Concurrent cache writes use distinct temporary names. | `changes_to_sample_archive_access_data_and_impulses_invalidate`, `replacing_a_sample_does_not_reuse_a_live_preload` |

Some relevant boundaries remain. Positional reads do not make a blocked OS read cancellable. Import and script initialization can only cancel at stage boundaries; final packing is not interruptible at every instruction. Loader phases serialize across instances, trading peak load throughput for a concurrency ceiling. Cache stamps are size/mtime based and can miss same-size edits with preserved timestamps. Preparing callback storage adds RAM; it does not make arbitrary dynamic allocation safe. Four workers are shared within one loaded plugin module, not across separately loaded CLAP/VST3 binaries or processes. Large script work may defer and change callback timing under small buffers; diagnostics make this visible. These changes do not establish unrestricted library support.

**Harp investigation:** the explicitly requested GPT-6.1-Sol agent (high reasoning) inspected Vista Harp and Pacific Normale/Harmonic. Vista had 2,000 zones; Pacific Normale/Harmonic had 4,160/1,280. None were missing or marked reversed. KSP key-off triggers dedicated release groups immediately, but those release layers contain rising envelopes: 140 ms AHDSR attacks, and Pacific also has a Flex with a 56 ms delay plus 84 ms rise. Muting the release groups removes most of the measured post-note-off swell. This rules out missing samples, actual reverse playback and a simple AHDSR release-sign bug in the tested patches.

Internal-modulator bypass, AHD-only and Flex Oneshot/loop switches remain undecoded. Pacific's release AHDSR first-byte flag is a plausible bypass marker, but the byte mapping is **unverified**; no production playback fix guesses it. Import warnings now identify this fidelity limit. Confirm with paired Kontakt presets differing only in bypass/Oneshot and reference renders using the same MIDI schedule, then implement the confirmed modes. Full local evidence: `artifacts/harp-investigation/REPORT.md` (ignored proprietary diagnostics/renders remain local). NI documents the intended [modulator parameters](https://docs.native-instruments.com/ni-tech-manuals/ksp-manual/en/engine-parameters) and [Flex behavior](https://docs.native-instruments.com/ni-tech-manuals/kontakt-manual/en/modulation); those documents do not prove private NKI byte mappings.

**Assessment of Opus's build work:** keep runtime-dispatched SIMD, ThinLTO, stripped shipping symbols and panic unwinding. Its CPU audit uses instruction counts and a meaningful -120 dBFS filter regression rather than claiming bit identity for regrouped sums. The separate fresh test above supports the instruction reduction, but does not independently validate its 5–12% PGO claim or its Windows package. `tools/pgo.sh` defaults to synthetic-only training when `KONTRA_PGO_LIBRARIES` is unset; per-library failures are suppressed, it chooses the first filesystem NKI and it trains natively even when the final command receives a cross target. Two stated reasons need correction: optimization level `s` preserves loop vectorization, while `z` disables it ([Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)); BOLT supports ELF shared objects, not just Linux executables ([LLVM BOLT](https://github.com/llvm/llvm-project/blob/main/bolt/README.md)). Neither correction is a reason to adopt size optimization or BOLT for DSP without evidence. Nightly tricks primarily concern edit/build throughput, so stable optimized shipping builds do not settle their development value.
