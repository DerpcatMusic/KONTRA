## What is implemented

- **Formats**: Kontakt `.nki` (script, zones, effects, UI), UVI/Falcon, SFZ,
  native. Picture containers (`.nkr`/`.nkx`) with sidecar metadata.
- **KSP**: the script VM, the UI/control model, `mf_*` MIDI object, string-array
  control parameters, `$KSP_TIMER` on the CPU clock.
- **DSP**: filters, dynamics, drive, delay (Modern + Choral banks), reverb,
  spatial, modulators; Hot Solo+ amp measured at Electric Mint's operating point.
- **Host/plugin**: CLAP + VST3, a rack with parts, a browser, an editor, and a
  one-slot ring so a control edit applies even when the host renders no audio.

## What is *not* verified — do not cite these as facts

- **Only the Sound Preset panel is compared to a live Kontakt capture.** The
  whole-page pixel check is a *regression golden* of our own render, so it can
  only see that the page changed. The panel row diffs a 177x69 crop of Kontakt
  8.14.1's own capture and can fail a build on a panel that was wrong to begin
  with. Everything else on the page — pictures, keyboard, the rest of the
  layout — is still checked for change only. `tools/oracle-mcp` can screenshot
  the whole page, and that remains the on-demand check.
- **Parity is measured on one note, on fourteen instruments, from two libraries.**
  There is no articulation matrix and no regression history; the Glory Days rows
  are one note at key 60, vel 100, CC1 127 on one MIDI, so keyswitch articulations,
  the section multis played as chords, and every other controller are unmeasured.
- **`wave_r` is not a parity statistic** for a single note: Kontakt correlates
  0.604 against itself within a session.
- **Click coordinates in the oracle are fixed**, not resolution-independent.
- **A `ui_xy`'s cursors are not drawn.** The click changes the instrument's state
  (`$CONTROL_PAR_ACTIVE_INDEX`, the keyswitch), but KONTRA has no pass that draws
  a pad's cursor or its `$CONTROL_PAR_CURSOR_PICTURE`, so a selected row does not
  light up on screen.
- **`dump.py` does not run as shipped** — its default EXE path does not exist on
  this machine and its `WINEDLLOVERRIDES=…=b` override is the wined3d assumption
  the oracle disproved.

## How to check the tree

```
tools/verify.sh            # the delivery gate: every row it prints must pass
tools/verify.sh --quick    # everything except the audio render
tools/verify.sh --portable # only the rows a CI runner can run; prints PORTABLE
                           # PASSED, never VERIFY PASSED
```

`.github/workflows/gate.yml` runs `--portable` on every PR to `main`: the same
script and the same rows, restricted to those that need nothing from a local
disk. It reports the library, render, `ui-drive` and pixel rows as **not run**
rather than skipped, because on this project "skipped" has been read as
"passed".

`VERIFY PASSED` means every row of that one table passed: the twelve test rows
(eleven crates plus the parity regressions, which read "skipped" without a
library), the plugin build and its CLAP entry, `rustfmt` and `clippy` on
first-party code, the gate's own self-tests (parsers, build-slot, pixel-diff),
Electric Mint loading and rendering completely — no missing sample frames, no
clipping, `init unanswered` and `actions_unhandled` under their ceilings, and
the audio fingerprint printed — a library free of probe copies, `ui-drive` on
both pages, `pixel diff vs golden`, `pixel diff vs Kontakt panel`, and the
**three-case** parity corpus. It does **not** mean the instrument matches
Kontakt: that is the oracle's job, it is on demand, and 17 of the corpus's 20
cases only run under `tools/parity-corpus/run.py`.
